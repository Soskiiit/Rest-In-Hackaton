## ❓ Вопросы жюри

### «Покажите правило 10%»
→ HUD: процент данных мира и «Чанков: ≤ 9 / 100»
→ Пересечь границу чанка → WS Messages: сначала `CHUNK_UNLOAD`, потом `CHUNK_LOAD`, следом `WORLD_STATS`
→ В `WORLD_STATS`: `data_percent` (байты JSON чанков) и `chunk_percent` — сервер режет AOI так, чтобы `data_percent` ≤ 10
→ DevTools → Memory → Heap Snapshot до/после перехода → Comparison: меши удалены (это часть DEV-C)
→ Консоль:
```js
Array.from(world.loadedChunks.keys())   // максимум 9 элементов
```
> ⚠️ Требует от DEV-C: `window.world = world` в `main.ts`.
> Честная формулировка: сервер ограничивает **переданные данные мира**; RAM/GPU клиента доказываем снимком Memory.

### «Что будет без интернета?»
→ Физически отключить роутер от интернета / выдернуть WAN-кабель
→ Всё продолжает работать: Go-бинарник, SQLite-файл, локальная LLM, клиент с Vite
→ Network tab: все запросы на `localhost` / `192.168.x.x`, ни одного внешнего CDN

### «Где хранится состояние?»
→ F5 → игрок на том же месте с тем же балансом и инвентарём
→ Ctrl+C на сервере (штатная остановка сохраняет позиции) → `./bin/server` → войти → прогресс на месте
→ Терминал:
```sql
SELECT login, profile, pos_x, pos_z, balance FROM players;
SELECT p.login, k.word_id FROM known_words k JOIN players p ON p.id = k.player_id;
SELECT npc_id, state, mianzi, aggro, current_price, version FROM npc_scenes;   -- общая сцена NPC
SELECT npc_id, player_id, mianzi, aggro, history_json FROM npc_relations;      -- личная память о каждом игроке
SELECT trade_id, player_id, item_id, amount FROM purchases;                    -- квитанции
```

### «В чём адаптивность NPC?»
→ Диалог 1: грубить → Aggro растёт → кричит КАПСОМ
→ Диалог 2: извиниться + похвалить → Mianzi > 70 → FLATTERED → скидка
→ «Последние 6 реплик с каждым игроком — в `npc_relations.history_json`, общий разговор — в `npc_scenes`; LLM видит обе истории в промпте»
→ Охранник Чжан (7_2): попытка взятки → Aggro = 100 независимо от ответа модели — правила держит сервер, не LLM

### «Почему WebSocket, а не polling?»
→ Network → WS → Messages: живые фреймы `PLAYER_MOVE`, `NPC_SPEECH`, `NPC_STATE`, `WORLD_STATS`
→ «Go + gorilla/websocket, Hub: горутина на клиента, ping каждые 20 с»

### «Как устроена авторизация?»
→ bcrypt-хэш пароля, JWT HS256 на 8 часов, токен проверяется **до** upgrade WS
→ Чужой Origin → 403; второй вход той же учёткой закрывает старую сессию

### «Почему такой стек?»
| Слой | Выбор | Аргумент |
|------|-------|----------|
| Backend | Go + gorilla/websocket | Горутины, один бинарник, stdlib `net/http` |
| БД | SQLite (WAL) | Встраиваемая, ноль настройки, транзакции — покупка не спишет деньги дважды |
| AI | Qwen3.5-4B локально | CPU, ~3–4 GB RAM, нативный китайский, JSON-ответ проверяется сервером |
| Клиент | Three.js + Vite | WebGL/WebGPU, InstancedMesh (1000 фонарей = 1 draw call) |
| TTS | Web Speech API | Оффлайн, без внешних сервисов |

### «Как добавить новое (День 2)?»
→ Новое слово/NPC/товар — в `server/world/catalog.json`, размещение — в `server/world/chunks/X_Z.json`, промпт — в `ai/prompts/`
→ Сервер при старте проверяет чанки и каталог: ошибка в данных не даст ему запуститься
