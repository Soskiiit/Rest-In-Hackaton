## 1. Подготовка

### 1.1. Тестовые аккаунты

Нужны два **разных** аккаунта: одна учётная запись допускает только одну активную сессию.
Разные профили дают разный стартовый словарь и, как следствие, разные субтитры `[???]`.

```bash
curl -s -X POST localhost:3000/auth/register -H 'Content-Type: application/json' \
  -d '{"login":"player1","password":"password123","profile":"business"}'

curl -s -X POST localhost:3000/auth/register -H 'Content-Type: application/json' \
  -d '{"login":"player2","password":"password123","profile":"culture"}'
```

| Аккаунт | Профиль | Знает изначально |
|---|---|---|
| `player1` | `business` | Числа, деньги, торг |
| `player2` | `culture` | Предметы, приветствия, этикет |

### 1.2. Чек-лист перед выходом к жюри

- [ ] `python ops/monitor.py` — все сервисы в статусе ✅ (AI не в режиме `mock`), предупреждений нет
- [ ] Игрок 2 входит со второго устройства без ошибки `403 ORIGIN_DENIED`
- [ ] HUD у обоих игроков показывает `WS: ONLINE`, а не `WS: MOCK DEMO`
- [ ] Выполнен пробный диалог с Лао Ваном (модель прогрета)
- [ ] У `player1` есть история грубого общения с Лао Ваном
- [ ] Ноутбук подключён к питанию, уведомления отключены, яркость максимальная
- [ ] В DevTools открыты вкладки **Network → WS → Messages**, **Memory**, **Console**
- [ ] В терминале открыта БД: `docker compose -f server/compose.yaml exec db psql -U hackaton -d hackaton`
- [ ] Текущее стабильное состояние закоммичено и отмечено тегом `checkpoint-N`

## 2. Сценарий демонстрации

Оба игрока появляются в точке (110, 110). Лао Ван и его товары находятся в центральном павильоне (100, 124), чанк `5_6`.

| № | Действие | Что видит жюри |
|---|---|---|
| 1 | Игрок 1 открывает `localhost:5173` и авторизуется | Вход в 3D-мир |
| 2 | Игрок 2 входит со второго устройства | Оба игрока видят друг друга |
| 3 | Игрок 1 подходит к Лао Вану и начинает диалог | Реплика NPC и четыре варианта ответа |
| 4 | Сравнить субтитры на двух экранах | Вторая строка различается: каждый видит перевод только известных ему слов |
| 5 | Игрок 1 выбирает «Это подделка!» | Растёт шкала агрессии, NPC обижается |
| 6 | Игрок 2 выбирает извинение | Агрессия снижается: сцена с NPC общая для всех участников |
| 7 | Калькулятор: игрок вводит сумму ниже порога | Торг сорван, NPC раздражён, баланс не изменился |
| 8 | Повторный торг и покупка `jade_amulet` | Списание только с кошелька покупателя, предмет в его инвентаре |
| 9 | Осмотр чайника (E), квиз, верный ответ | Слово 茶壶 (`word_teapot`) переводится прямо в текущей реплике |

**Если ответ модели задерживается:** пояснить, что модель работает на CPU хост-ноутбука без облака.
При недоступности модели сервер переключается на резервный конечный автомат (`fallback: true` в `NPC_SPEECH`) — это следует назвать прямо, не выдавая его за ответ LLM.

**Если сервер недоступен:** клиент открывается в автономном режиме `http://localhost:5173/?demo=true` (HUD: `WS: MOCK DEMO`).
Режим показывает только интерфейс и локальную логику клиента; жюри сообщается об этом прямо.

## 3. Ответы на вопросы жюри

### 3.1. Как соблюдается правило 10%?

1. HUD: доля загруженных данных мира и счётчик чанков (не более 9 из 100).
2. Пересечь границу чанка. В **Network → WS → Messages** видна последовательность `CHUNK_UNLOAD` → `CHUNK_LOAD` → `WORLD_STATS`.
3. В `WORLD_STATS` показать `data_percent` (объём JSON чанков) и `chunk_percent`. Сервер ограничивает зону видимости так, чтобы `data_percent` не превышал 10.
4. **Memory → Heap Snapshot** до и после перехода, режим Comparison: геометрия выгруженных чанков освобождена.
5. Консоль:
   ```js
   Array.from(world.loadedChunks.keys())   // не более 9 элементов
   ```

> Формулировка для жюри: сервер ограничивает объём **переданных данных мира**; потребление памяти клиентом подтверждается снимком Memory.

### 3.2. Что произойдёт без интернета?

1. Отключить WAN на роутере.
2. Игра продолжает работать: Go-сервер, PostgreSQL в Docker, локальная LLM и клиент находятся в LAN.
3. Во вкладке Network все запросы идут на `localhost` или `192.168.x.x`; внешних CDN нет.

### 3.3. Где хранится состояние?

1. F5 — игрок появляется на прежнем месте с тем же балансом и инвентарём.
2. Штатно остановить сервер (Ctrl+C) и запустить снова — прогресс и состояние NPC восстановлены.
3. Показать данные в PostgreSQL:

```sql
-- Игроки
SELECT login, profile, pos_x, pos_z, balance FROM players;

-- Личный словарь
SELECT p.login, k.word_id
FROM known_words k JOIN players p ON p.id = k.player_id;

-- Общее состояние NPC
SELECT npc_id, state, mianzi, aggro, current_price, version FROM npc_scenes;

-- Память NPC о каждом игроке
SELECT npc_id, player_id, mianzi, aggro, history_json FROM npc_relations;

-- Квитанции покупок
SELECT trade_id, player_id, item_id, amount FROM purchases;
```

### 3.4. В чём адаптивность NPC?

1. Диалог 1: грубость — агрессия растёт, NPC переходит на крик.
2. Диалог 2: извинение и комплимент — уважение выше 70, состояние `FLATTERED`, скидка.
3. Пояснение: последние шесть реплик с каждым игроком хранятся в `npc_relations.history_json`, общий разговор — в `npc_scenes`; обе истории передаются модели в промпте.
4. Охранник Чжан (чанк `7_2`): попытка взятки приводит к агрессии 100 независимо от ответа модели — ключевые правила обеспечивает сервер.

### 3.5. Почему WebSocket, а не polling?

Вкладка **Network → WS → Messages**: поток кадров `PLAYER_MOVE`, `NPC_SPEECH`, `NPC_STATE`, `WORLD_STATS`.
Сервер на Go с gorilla/websocket: отдельная горутина на клиента, heartbeat через ping/pong.

### 3.6. Как устроена авторизация?

- Пароли хранятся в виде bcrypt-хэша.
- Сессия — JWT HS256; токен проверяется до установки WebSocket-соединения.
- Запросы с неразрешённого Origin отклоняются (403); повторный вход тем же аккаунтом закрывает предыдущую сессию.

### 3.7. Почему выбран такой стек?

| Слой | Технология | Обоснование |
|---|---|---|
| Сервер | Go, gorilla/websocket | Горутины, единый бинарный файл, стандартный `net/http` |
| Хранилище | PostgreSQL 18.6 в Docker | Транзакции и блокировки строк защищают личные кошельки и общий торг |
| AI | Qwen3.5-4B, локально | Работа на CPU, нативный китайский, ответ проверяется сервером по схеме |
| Клиент | Three.js, Vite | WebGL/WebGPU, InstancedMesh — множество объектов за один draw call |
| Озвучка | Web Speech API | Работает офлайн |

### 3.8. Как расширять мир?

- Слова, NPC и товары описываются в `server/world/catalog.json`.
- Размещение объектов — в `server/world/chunks/X_Z.json`.
- Характер NPC — промпт в `ai/prompts/`.
- При запуске сервер валидирует каталог и чанки: некорректные данные не попадут в игру.

## 4. Регрессионный прогон

Выполняется двумя устройствами (`player1` и `player2`). Статус: ✅ — пройдено, ❌ — дефект.

### 4.1. Сеть и сессии

| ID | Проверка | Ожидаемый результат | Статус |
|---|---|---|---|
| NET-01 | Вход `player2` со второго устройства | Вход успешен, клиент обращается к IP хоста | |
| NET-06 | Вход с логином и паролем | HUD: `WS: ONLINE`; в Network WS-запрос `/ws?token=…`, без перехода в `MOCK DEMO` | |
| NET-07 | Вход с неверным паролем | Сообщение об ошибке, вход в мир не выполнен | |
| NET-02 | Перемещение обоих игроков | Аватары видны друг другу, движение плавное | |
| NET-03 | Закрыть вкладку `player2` | Аватар `player2` исчезает у `player1` | |
| NET-04 | Повторный вход `player1` во второй вкладке | Первая сессия закрыта (код 1008), пользователь видит сообщение | |
| NET-05 | Отключить WAN на роутере | Игра продолжает работать | |

### 4.2. Мир

| ID | Проверка | Ожидаемый результат | Статус |
|---|---|---|---|
| WLD-01 | Переход через границу чанка | Загружено не более 9 чанков; `CHUNK_UNLOAD` приходит раньше `CHUNK_LOAD` | |
| WLD-02 | Уход из зоны | Объекты старых чанков удалены со сцены | |
| WLD-03 | Сравнить HUD и последний `WORLD_STATS` | Процент кеша в HUD равен `data_percent`, не `chunk_percent` | |

### 4.3. Диалоги и словарь

| ID | Проверка | Ожидаемый результат | Статус |
|---|---|---|---|
| DLG-01 | Начать диалог с Лао Ваном | Приходит `DIALOGUE_PENDING`, затем реплика; движение и чат не блокируются | |
| DLG-02 | Повторно выбрать уже использованный вариант | Ошибка `STALE_CHOICE`, кнопки обновлены | |
| DLG-03 | Сравнить субтитры `business` и `culture` | Наборы `[???]` различаются | |
| DLG-04 | Квиз чайника, верный ответ | `WORD_LEARNED`, перевод появился в текущей реплике | |
| DLG-05 | Игрок на расстоянии 5–15 от NPC | Реплика видна, варианты ответа недоступны | |
| DLG-06 | Остановить AI-сервис | NPC отвечает резервными репликами, в отладке виден `fallback` | |

### 4.4. Торговля

| ID | Проверка | Ожидаемый результат | Статус |
|---|---|---|---|
| TRD-01 | Сумма ниже порога | `rejected`, баланс не изменён, агрессия выросла | |
| TRD-02 | Успешная покупка | Обновлены `BALANCE` и `INVENTORY` | |
| TRD-03 | Повторная покупка того же предмета | `ITEM_ALREADY_OWNED` | |
| TRD-04 | Одновременная покупка двумя игроками | Один успех, второй — `STALE_TRADE`; после нового торга покупка доступна и ему | |
| TRD-05 | Подтверждение после истечения срока предложения | `TRADE_EXPIRED` | |
| TRD-06 | Повар Чэнь (`3_5`) | Продаёт лапшу | |
| TRD-07 | Охранник Чжан (`7_2`), попытка взятки | Торговля недоступна, состояние `AGGRO` | |

### 4.5. Персистентность

| ID | Проверка | Ожидаемый результат | Статус |
|---|---|---|---|
| PRS-01 | Обновить страницу (F5) | Позиция, баланс, словарь и инвентарь сохранены | |
| PRS-02 | Перезапуск сервера | Прогресс игроков и состояние NPC восстановлены | |
| PRS-03 | Перезапуск контейнера БД (`docker compose -f server/compose.yaml restart db`) | После переподключения данные на месте | |

## 5. Оформление дефектов

Каждый дефект передаётся в командный чат в следующем формате:

```
[ID проверки] Краткое описание
Шаги:       1. … 2. … 3. …
Ожидалось:  …
Фактически: …
Код ошибки: значение из пакета ERROR (если есть)
Окружение:  устройство / браузер / аккаунт
```
